# 妙手记录

## 2026-05-17 - 对话中的关键发现

---

### 1. 问题的根源：初始化 prompt，不是每条消息

**发现**：之前一直认为"每次交互注入的 token 决定了延迟"，但真正导致 MiniMax M2.7 首字延迟 10 秒的原因，是 session 开始时 buildSystemPrompt 那叠纸太厚。每条消息的增量成本很薄，真正贵的是 session 初始化。

**含义**：优化目标应该是 initialization prompt 的体积，而不是每轮动态注入的记忆量。

---

### 2. Context rot — 加 context 不仅慢，还会让 LLM 变笨

**发现**：Anthropic 的研究发现，每添加一个 token，LLM 的"注意力预算"被消耗一点，处理后续信息的质量随之下降。这是 attention 机制 O(n) 的固有成本，不是线性的，是同步的。意味着更长的 prompt = 更慢 + 更差的输出。

**含义**：prompt 越长越贵，这里有两个独立的成本。砍 prompt 不只是加速，是同时提升质量。

---

### 3. Token 预算 vs 组块数 — 把硬约束换到正确的地方

**发现**：旧设计用"7个槽"作为硬截断，这是工程师的配置，不是物理约束。正确的方式是用 token 预算（~2300 tokens）作为唯一硬约束，让组块数作为 emergent 结果。数量由空间决定，不由工程师决定。

**含义**：设计要承认唯一的不可违反约束是物理的（token 数量 / attention 预算），其余的都应该是 emergent。

---

### 4. 无截断不是"传所有节点"，而是"让 context 窗口自己截断"

**发现**：之前讨论"不截断"时误解了——不是把所有节点的内部状态全部传给 LLM，而是只传格式化后的文本摘要（每个节点 50-80 字）。传给 LLM 的量由 context 窗口决定，不由算法决定。节点的激活值、边权重是算法自己用的，不出现在 prompt 里。

**含义**：算法的复杂度和传给 LLM 的信息量是两个不同维度。

---

### 5. 节点内容质量取决于 LLM，不取决于算法

**发现**：节点的"训练"是 LLM 自己的摘要行为，不是算法学出来的。LLM 决定要不要输出 `<memory_node>`，写什么 summary，字多字少完全由 LLM 自己决定。算法只负责管理节点之间的连接，不控制内容。

**含义**：系统的上限被 LLM 的摘要意愿和质量卡住了。算法给了记忆写入的能力，写什么内容是 LLM 的选择，这是不可控的。

---

### 6. 长期记忆 vs 短期记忆的矛盾 — pruning 是天花板

**发现**：v2 的 pruning 规则在超过 500 节点时触发，删低激活的。这意味着 500 节点约等于半年的记忆容量。更早的记忆不管多重要，只要激活低就会被删。"两年后还认识你"这件事在当前设计里不可能实现。

**矛盾**：节点上限让算法永远快，但也让长期记忆永远丢失。

---

### 7. 分层保护 — 不是设计的暴政，是涌现的条件

**发现**：身份锚点（人格、偏好、说话方式）不应该参与普通 pruning。这些信息激活频率可能很低，但一旦被删，系统就会失去"认出用户"的能力。需要一个独立的保护层，或者更高的权重。让这些节点不受竞争压力影响。

**为什么不是暴政**：保护层不是在规定结果，而是给涌现一个稳定的环境。围栏不是为了让植物长成围栏的样子，而是为了让它们有空间慢慢长。保护是让系统有持久性的必要条件，而不是控制它的手段。

---

### 8. 小设计的合法性 — 涌现需要最小设计

**发现**：完全无设计的涌现系统无法维持长期记忆，无法形成稳定的模式。适当的"小设计"（节点上限、分层保护、token 预算）是让涌现有意义的必要条件。这些设计的存在是为了保护涌现的条件，不是为了规定涌现的结果。

**哲学一致性**：这与"土壤工程师"的哲学一致——调节 pH 值、提供营养、给时间，不是规定植物长成什么样。

---

### 核心结论

```
问题不在记忆系统，在于 initialization prompt 太厚
优化目标：初始化体积，不是每轮注入量

context rot 告诉我们：更多 token = 更慢 + 更笨，两个成本同时存在

涌现需要持久性，持久性需要保护层
保护层 = 小设计，不是大设计
小设计的目的：保护涌现的条件，不是规定涌现的结果

两年记忆需要的节点数 ≈ 1400
保护层让身份锚点不受 pruning 影响
算法永远快（毫秒级），慢的是网络
```

---

### 9. Backup 向量数据库 — 记忆网络的"第二大脑"

**发现**：花子的内部记忆网络（MemoryEngine）是实时运转的短期记忆，但重启后会丢失。为了让花子拥有"永不丢失的长期记忆"，设计了一个 backup 数据库作为辅助。

**架构**：
```
用户 query
  → 脚本调用本地 embedding 模型（bge-small-zh-v1.5）算向量
  → Chroma 向量数据库做 top-K 相似度搜索
  → 取回筛选结果（原文 + metadata）
  → 格式化成 context 发给 LLM
```

**关键决策：为什么不用 embedding 做检索**
- 花子本身是 LLM，天生擅长理解语义和推理关系
- embedding model 做 similarity search 是检索效率工具，不是理解工具
- LLM 直接读自然语言比通过 embedding 间接读更直接
- 向量搜索是"语义兜底"，标签路由是日常效率

**部署方案**：
- embedding 模型：bge-small-zh-v1.5（240MB，12GB VRAM 绑绑有余）
- 向量数据库：Chroma（单文件本地存储，Python/JS 客户端）
- 不需要额外框架，Python 脚本 + Chroma + huggingface Transformers 即可

**适用场景**：当花子"忘记"了某个关键记忆时，可以从 backup DB 里检索上下文，保持对话连续性。backup DB 存储所有历史对话的完整记录，花子是主动读取者。

**数据规模考量**：
- 2000 节点以下：标签路由足够，不需要 embedding
- 2000 节点以上：标签变细碎，embedding 的语义匹配开始发挥作用
- Backup DB 规模取决于历史对话量，用户预期"几千条"时标签够用，"百万级"时需要 embedding

---

### 10. 腾讯 Agent Memory vs 我们的 Backup DB — 底层逻辑对比

**发现**：腾讯TDB Agent Memory 是一个四层渐进式抽象系统（L0原始归档 → L1语义提取 → L2场景图谱 → L3用户画像），核心设计是"活的记忆工厂"——自动捕获、自动整理、自动遗忘。我们的Backup DB是"死的图书馆"——你翻它动，不翻不动。

**对与我们use case的客观评价**：

腾讯方案在我们的场景下**过度设计**。四层架构中的L2 Offload（场景图谱）、L3 Persona自动生成、异步Pipeline、后端LLM调用——全是多余，我们用不上，还增加复杂度。

**但有三个设计值得借鉴**：

1. **语义去重阈值 0.85**：新消息和L1做embedding相似度比对，超过0.85跳过提取，防止记忆无限膨胀。直接用。

2. **L0原始归档思路**：存原始文本（不压缩）作为最终兜底。用于语义去重的比对源，也用于崩溃恢复。

3. **增量处理**：不是每轮全量跑，只处理新消息。Checkpoint续跑。这让系统不随时间变慢。

**核心结论**：我们不需要腾讯那套复杂的记忆工厂，只需要：
```
对话 → 存原始文本 + 标签 → 用户问 → 向量召回 → 结果给花子
```
简单、本地、第二大脑、不多不少刚好够用。

## Appendix：MemoryEngine 完整设计规范（Phase 1-5）

### 文件结构
```
src/memory/
├── graph.ts         # MemoryGraph：节点与边的内存图
├── entry.ts         # EntryMatcher：分布式入口匹配 + extractEmotion/Keywords
├── activation.ts    # SpreadingActivation：10轮扩散引擎
├── competition.ts   # SlotCompetition：Top-7竞争+侧向抑制（Phase 5 已替换为token预算）
├── buffer.ts        # BufferManager：对话轮次Buffer
├── snapshot.ts      # SnapshotManager：异步JSON快照 + loadIntoGraph()时间补偿
└── index.ts         # MemoryEngine：主控制器（Phase 5 重构）

tests/memory/
├── phase1.test.ts   # 骨架验证
├── phase2.test.ts   # 基础功能
├── phase3.test.ts   # Hebbian / 衰减 / pruning
└── phase4.test.ts   # 人格从记忆涌现 + 工具记忆入网
```

### Phase 5 核心参数
| 参数 | 值 | 说明 |
|---|---|---|
| MEMORY_BUDGET | ~600 chars | Base Self + Buffer 后留给记忆的空间 |
| ROUND_COLD_START | 5 | 前5轮 broadcast/扩散正常，但不进 prompt |
| NODE_PRUNE_LIMIT | 2000 | 超过时删低激活孤儿节点 |
| ACTIVATION_INIT | 0 | 工具节点无初始激活，靠扩散 |
| SNAPSHOT_OLD_THRESHOLD | 30天 | 超过30天的旧节点 activation → 0.05 |
